## 二、全局技术栈

| 层 | 选型 |
|---|---|
| 后端 | Flask + SQLAlchemy + JWT + Flask-SocketIO |
| 数据库 | MySQL 8.0（主库 `jiaxing_rural`） + Redis（缓存 / 实时消息通道） |
| Web 前端 | Vue3 + Vite + Element Plus + ECharts + Leaflet |
| 移动端 | Uni-app（微信小程序，接入微信原生地图组件） |
| 部署 | 本地进程方式（本机无 Docker） |

## 三、核心功能需求（四模块，源自新版开题报告）

1. **基于 WebGIS 的农文旅资源空间展示**：两端均加载海宁市地图，标注**果园**与**古镇**等资源点位，点击 Marker 弹出图文详情；小程序端做小屏聚合与防重叠。
2. **特色资源发布与多端导览**：Web 后台负责图文资讯、特色农产品、古镇村落信息的发布与审核；小程序端作为游客展示窗口，提供分类浏览、详情查看与**外部购买链接导流**。
3. **平台运行数据可视化大屏**：ECharts 展示 PV/UV、村落与景点浏览热度排行、外链点击转化率——数据全部来自**系统真实运行日志**，不伪造宏观销售数据。
4. **基于 WebSocket 的多端实时同步**：小程序端产生浏览/点击行为 → 后端记录日志并统计 → 经 WebSocket 实时推送 Web 大屏，实现数据动态跳动，替代 HTTP 轮询。

## 四、硬性约束

- **零支付**：不实现下单、支付、退款；农产品一律跳转外链导流。
- 实时性必须真走 WebSocket，不得退化为轮询。
- 基本安全：JWT 鉴权、密码加盐哈希、后台操作留痕、CORS 白名单。
- Web 端自适应布局，兼容主流浏览器与不同屏幕尺寸。
- 不涉及爬虫；数据来源为初始化录入 + 真实运行日志。

## 六、数据模型（已落地）

| 表 | 说明 |
|---|---|
| `admin` | 后台管理员：username / password_hash / real_name / role / status / last_login_at |
| `attraction` | 农文旅点位：name / category(古镇·果园·村落·景区) / town / address / **longitude·latitude(Numeric(10,6))** / summary / description / external_url / status / view_count / sort |
