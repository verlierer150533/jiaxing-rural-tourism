## 一、这是一件什么作品

一个面向嘉兴海宁市的**乡村农文旅信息展示与服务平台**，由三部分组成：

| 部分 | 面向谁 | 做什么 |
|---|---|---|
| Web 管理后台 | 平台运营人员、管理员 | 维护果园/古镇/村落/景区资源，查看运营数据 |
| Web 实时数据大屏 | 运营人员、参观者 | 实时展示浏览量、访客数、外链点击、热度排行、资源地图与实时足迹 |
| 微信小程序端 | 游客（免注册） | 看推荐、按地图找目的地、看详情、一键导航、跳转外部购买链接 |

**两个关键定位**：

1. **不碰钱**。全平台没有支付、下单、退款，农产品与商品只做展示 + 跳转外链（"零支付纯导流"）。
2. **两端协同**。后台改一条资源，小程序和大屏立刻能看到；小程序有人浏览，大屏马上跳动。

技术栈：Flask + SQLAlchemy + JWT + Flask-SocketIO + MySQL + Redis；Vue3 + Vite + Element Plus + ECharts + Leaflet；Uni-app（微信小程序）。

## 二、怎么把它跑起来

### 2.1 最省事的方式：双击两个 bat

在项目根目录 `jiaxing-rural-tourism\` 下有两个批处理文件：

**第一步：双击 `启动后端服务.bat`**

它会自动做两件事：先看 6379 端口有没有 Redis，没有就用自带的 `tools\redis\redis-server.exe` 起一个；然后启动 Flask 后端。

看到这样的输出就算成功：

```
[1/2] 启动 Redis ...
[2/2] 启动 Flask 后端 ...
 农文旅平台后端启动  async_mode = eventlet
 健康检查 : http://127.0.0.1:5000/api/ping
```

> 这个窗口**不能关**，关掉就等于停掉后端。

**第二步：双击 `启动网页端.bat`**

它会先检查后端在不在线，然后用 Vite 启动前端，等服务就绪后自动帮你打开浏览器。

看到 `VITE ... ready` 且浏览器自动打开 `http://127.0.0.1:5173` 就算成功。

### 2.2 访问地址与账号

| 用途 | 地址 | 账号 |
|---|---|---|
| 管理后台 | http://127.0.0.1:5173/login | admin / admin123 |
| 运营概览 | http://127.0.0.1:5173/dashboard | 同上 |
| 资源管理 | http://127.0.0.1:5173/attraction | 同上 |
| **实时数据大屏** | http://127.0.0.1:5173/screen | 同上 |
| 后端健康检查 | http://127.0.0.1:5000/api/ping | 无需登录 |

### 2.3 小程序端（需要微信开发者工具）

```powershell
cd D:\homework\毕设\jiaxing-rural-tourism\miniprogram
npm run dev:mp-weixin
```

用微信开发者工具导入 `miniprogram\dist\dev\mp-weixin`（或已经构建好的 `miniprogram\dist\build\mp-weixin`），
**必须在「详情 → 本地设置」勾选"不校验合法域名"**，否则请求 `http://127.0.0.1:5000` 会被拦截。

### 2.4 手动启动（不想用 bat 时）

```powershell
# 1) Redis（可选）
tools\redis\redis-server.exe --port 6379 --bind 127.0.0.1 --save 3600 1

# 2) 后端
cd web-backend
python app.py

# 3) 前端
cd web-frontend
npm run dev
```

### 2.5 首次运行 / 数据被玩坏了想重置

```powershell
cd web-backend
python init_db.py --demo --reset-logs
```

会重建表、写入 1 个管理员、12 个资源点位和近 7 天约 400+ 条演示日志。

## 四、常见问题

### Q1：打开 `http://127.0.0.1:5000` 显示 404，是不是后端坏了？

**不是。** 5000 端口只提供 API（`/api/...`），根路径本来就没有页面，返回 404 属于正常。
要判断后端是否正常，请看 **`http://127.0.0.1:5000/api/ping`**，能返回下面这样的 JSON 就说明一切正常：

```json
{"code":0,"message":"pong","data":{"async_mode":"eventlet","database":"jiaxing_rural",
 "redis":true,"message_queue":"redis","ws_namespace":"/ws"}}
```

**界面在 5173 端口**，需要另外启动 `启动网页端.bat`。

### Q2：双击 bat 后窗口一闪就没了

- 检查 Python 是否在 PATH 里：新开一个命令行敲 `python --version`，能出版本号才算正常；
- 如果提示"没找到 python"，把 Python 安装目录加入系统环境变量 PATH 后重试。

### Q3：提示端口被占用（Address already in use）

说明后端或前端已经有一个在跑了。先看看任务栏是不是已经开着一个黑窗口；要强制结束：

```powershell
Get-NetTCPConnection -LocalPort 5000 | Select-Object OwningProcess
Stop-Process -Id <上面查到的PID> -Force
```

### Q4：`/api/ping` 里 `redis` 是 `false`

Redis 没起来。不影响主流程（会自动退化成无缓存），但大屏的跨进程推送和地图缓存会失效。
重新双击 `启动后端服务.bat` 即可，它会自动拉起 Redis。

### Q5：小程序里所有请求都失败

没勾"不校验合法域名"。真机演示时还要把 `miniprogram\src\config.js` 里的 `127.0.0.1` 改成电脑的局域网 IP（例如 `http://192.168.1.10:5000/api`）。

### Q6：`npm run build` 报 `Access is denied`

esbuild 清理临时文件被拦截。构建前先设置临时目录：

```powershell
$env:TEMP = '.\web-frontend\.tmp'; $env:TMP = $env:TEMP
npm run build
```

### Q7：地图上的点位和实际位置有偏差

已知问题。现有坐标取自公开地图初值，与微信地图使用的 GCJ-02 坐标系存在偏移，正式上线前需统一坐标系并人工校准。
