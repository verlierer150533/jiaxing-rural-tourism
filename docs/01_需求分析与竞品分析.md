# 需求分析与竞品分析

> 项目：基于WebGIS的海宁乡村农文旅服务平台设计与实现
> 文档类型：05_文案 · 分析文档
> 版本：v1.0（2026-11）

---

## 一、项目背景与问题界定

### 1.1 政策与区域背景

浙江省自 2018 年起以"数字乡村 + 未来乡村"双轨推进农业农村信息化。据张彬凯等（2023）对浙江政府采购网与省公共资源交易服务平台 **2021 年 1 月—2022 年 7 月共 19 个月、125 个数字乡村领域政府信息化项目**的统计：

- 县（市、区）级 61 个、乡镇（街道）级 47 个，**两级合计占 86.4%**；
- 乡村数字治理 54 个、乡村数字经济 44 个，**两大场景合计占 78.4%**；
- **74.4% 的项目金额低于 300 万元，90.4% 低于 500 万元**；
- 首批国家数字乡村试点中，嘉兴平湖"金平湖数字乡村大脑"入选。

这组数据说明两件事：其一，数字乡村建设的主战场已经下沉到县域与乡镇；其二，主流形态是"小规模、场景化、轻量投入"的应用，而不是大而全的政务系统。**本课题选择在海宁市（县级市）尺度上做一个轻量平台，与该分布规律一致。**

### 1.2 本地痛点

嘉兴"种粮宝"（余洋等，2024）代表的是**政府监管与服务端**：它通过数据仓 + 管理端 + 服务端三段式架构，把粮食补贴办理从 9 步压缩到 3 步、发放周期从 5 个月缩短到 10 个工作日，并实现省—市—县—乡—村五级数据联动。但其业务链聚焦"粮食生产与补贴"，**不面向公众提供农文旅内容消费与空间导览**。

沈项阳（2025）指出的浙江困境中，有两条与本题高度相关：

1. **"地方特色应用与省级平台融通不够、实用性不强"**——大量系统重建设、轻运营，重展示、轻实效；
2. **"农村居民数字素养整体较低"**——要求产品形态必须足够轻，不能指望农户或游客去装 App、学操作。

姚清晨等（2026）在 197 篇文献的系统综述中提出"技术嵌入—为人赋能"张力框架，并归纳出数字缺失、**数字悬浮**、数字鸿沟、**数字负担**、数字形式主义五类困境。其中"数字悬浮"（新治理架构脱离实际需求而悬置）与"数字负担"（多套系统重复填报）对本项目的反向约束最为直接。

### 1.3 问题界定（本项目要解决什么）

| 编号 | 问题 | 现状证据 | 本项目对策 |
|---|---|---|---|
| P1 | 乡村农文旅资源信息分散，游客难以"按空间"找到目的地 | 资源信息散落在公众号、短视频、团购平台 | WebGIS 地图统一标注果园/古镇/村落/景区，两端均可浏览 |
| P2 | 缺乏面向公众的乡村资源展示窗口，已有平台多为政务端 | "种粮宝"面向监管，非公众端 | 小程序作为唯一游客入口，免安装、低门槛 |
| P3 | 平台运营方看不到真实客流与内容热度，无法评估效果 | 单机工具或纯静态展示页 | 全量浏览足迹入库 + 实时大屏 |
| P4 | 通用电商平台入驻门槛高，乡村商户难以承接交易 | 通用平台佣金与运营成本高 | **零支付纯导流**：只做展示与跳转，不碰交易 |
| P5 | 多端数据不同步，后台看到的与游客看到的不一致 | 传统方案靠人工导出或轮询 | 单一后端 + WebSocket 实时推送 |

## 二、调研设计

### 2.1 调研方法

采用**文献研究法 + 案例分析法 + 问卷调查法 + 原型迭代法**四者结合（对应开题报告 5.1）：

1. **文献研究**：梳理 15 篇中英文文献，形成政策—现状—技术三层论证；
2. **案例分析**：拆解"种粮宝"、平湖"金平湖数字乡村大脑"、通用 OTA 与电商平台的功能与短板；
3. **问卷调查**：面向本校学生与海宁周边游客发放，验证使用意愿与功能偏好；
4. **原型迭代**：先做静态原型，再分模块开发，边开发边验证。

## 三、竞品分析

### 3.1 竞品选取

| 类别 | 竞品 | 选取理由 |
|---|---|---|
| 本地政务平台 | 嘉兴"种粮宝" | 同区域、最具代表性的农业信息化平台 |
| 本地数字乡村平台 | 平湖"金平湖数字乡村大脑" | 首批国家级试点，同属嘉兴市域 |
| 通用 OTA | 携程 / 飞猪 | 乡村游内容最丰富的商业化平台 |
| 通用内容平台 | 抖音 / 小红书 | 目前乡村游信息的主要实际来源 |
| 通用电商 | 淘宝 / 拼多多 | 农产品上行的主流渠道 |

### 3.2 对比矩阵

| 维度 | 种粮宝 | 金平湖大脑 | 通用 OTA | 内容平台 | 通用电商 | **本项目** |
|---|---|---|---|---|---|---|
| 主要服务对象 | 政府监管部门、种粮主体 | 政府、村级管理 | 大众游客 | 大众用户 | 消费者、商家 | **游客 + 平台运营方** |
| 核心业务 | 补贴发放、田块管理 | 乡村治理、产业监测 | 交易与预订 | 内容分发 | 商品交易 | **展示 + 导览 + 导流** |
| 空间可视化 | 图斑定位（管理视角） | 有 | 有 POI 地图 | 弱 | 弱 | **WebGIS 资源地图（两端）** |
| 多端形态 | 浙里办/浙政钉 + 后台 | PC + 移动 | App + 小程序 | App | App + 小程序 | **Web 后台 + 微信小程序** |
| 实时性 | 数据同步（业务级） | 监测大屏 | 弱 | 无 | 无 | **WebSocket 秒级推送** |
| 是否涉支付 | 否（补贴） | 否 | 是 | 部分 | 是 | **否（零支付）** |
| 入驻/使用门槛 | 高（需政务身份） | 高 | 中（商家入驻） | 低（但需运营账号） | 中高（保证金/佣金） | **低（游客免注册）** |
| 对本项目启示 | 数据仓 + 分级权限 | 大屏指标设计 | 空间检索体验 | 内容吸引力 | 交易链路复杂，不必自建 | — |

### 3.3 竞品短板与本项目机会

1. **政务平台"看得见数据、看不见游客"**：种粮宝的数据仓服务于监管决策，其"地图图斑"是管理者视角，游客无法据此规划行程。→ 本项目把同一套空间数据换成**游客视角的资源地图**。
2. **通用平台"内容多、但不本地"**：OTA 与内容平台的乡村信息由商家或博主自发上传，存在信息陈旧、位置不准、同质化严重的问题。→ 本项目由**运营方统一维护**，数据唯一来源、后台可审核。
3. **通用电商"交易重、乡村接不住"**：中小合作社难以承担入驻、佣金、客服与售后成本。→ 本项目**只做导流**，把交易留给成熟平台，自身专注"被发现"这一环。
4. **几乎没有产品把"实时客流"反馈给运营方**：乡村景区普遍不知道今天有多少人看了自己。→ 本项目用 WebSocket 把浏览足迹实时汇总成大屏，**这既是技术点，也是运营价值点**。

### 3.4 差异化定位

> 一句话定位：**面向海宁的"轻量级乡村农文旅入口"——游客用小程序看地图找目的地，运营方用 Web 后台管内容、看实时热度；不碰交易，只做被发现。**

## 四、用户角色与典型场景

### 4.1 角色

| 角色 | 描述 | 主要诉求 | 使用端 |
|---|---|---|---|
| 游客（未注册） | 本地居民、周边自驾游客、采摘客群 | 快速找到"去哪、多远、现在有什么" | 微信小程序 |
| 平台运营人员 | 文旅运营方/镇街工作人员 | 维护资源信息、审核内容、掌握热度 | Web 管理后台 |
| 系统管理员 | 技术维护者 | 账号、权限、日志、数据一致性 | Web 管理后台 |

> 说明：本平台不设"农户自主注册发布"角色。原因见 1.2 中"农村居民数字素养较低"的判断——让农户自己维护线上内容在县域场景中往往难以持续，改为**运营方代维护 + 电话/线下采集**更现实。

### 4.2 典型场景

**场景 1：周末找去处（核心场景）**
小王周六想带家人去海宁采摘。打开小程序 → 首页看到"杨梅正当季"与热门推荐 → 切到地图页 → 筛选"果园" → 地图上看到黄湾镇若干果园 → 点击一个 → 弹出卡片显示镇街与浏览量 → 进详情 → 点"打开微信地图导航" → 出发。

**场景 2：运营方维护内容**
运营人员在后台新增一个"袁花果园" → 填名称、类别、镇街、经纬度、简介、外链 → 保存 → 地图页缓存立即失效，小程序下次刷新即可看到。

**场景 3：大屏看热度**
活动当天，运营方打开 `/screen` 大屏。游客每次浏览详情，大屏 PV 数字跳动、右侧"实时足迹"滚动出现"浏览 · 大尖山果园 · 小程序"，热度排行实时变化。

**场景 4：外链导流**
游客在详情页点"前往第三方页面" → 系统记录一次 `click_external` → 复制链接并提示到浏览器打开 → 后台转化率指标随之变化。

## 七、需求取舍说明（写在论文"讨论"部分很加分）

1. **为什么不做支付**：交易会引入资金、退款、售后、发票与合规成本，且与"乡村中小主体承接能力弱"的现实不符。零支付把复杂度留给成熟电商，自身聚焦"被发现"。
2. **为什么不做农户自主发布**：县域场景中农户持续维护线上内容的成本过高，容易产生"僵尸信息"。改为运营方代维护，牺牲了规模换来数据质量。
3. **为什么用小程序而非 App**：免安装是降低数字门槛最有效的手段（对应沈项阳指出的"数字素养较低"）。
4. **为什么大屏只展示真实日志**：避免"伪造宏观销售数据"的形式主义陷阱（对应姚清晨等的"数字悬浮/数字形式主义"批评）。
