# 多端功能对照表

> 项目：基于WebGIS的海宁乡村农文旅服务平台设计与实现
> 文档类型：05_文案 · 多端功能对照表（作品规范明确要求项）
> 版本：v1.0（2026-11）

本表用于说明"同一业务在不同终端如何呈现"，并明确**哪些能力由后端共享、哪些是端侧特有**，以证明多端不是两套系统，而是同一后台的一体两面。

---

## 一、终端与角色总览

| 终端 | 形态 | 目标用户 | 主要职责 | 访问方式 |
|---|---|---|---|---|
| Web 管理端 | Vue3 + Element Plus（浏览器） | 平台运营人员、系统管理员 | 内容维护、资源审核、数据监控 | `http://127.0.0.1:5173` |
| Web 数据大屏 | Vue3 + ECharts（浏览器全屏） | 运营人员、参观领导 | 实时客流与热度可视化 | `http://127.0.0.1:5173/screen` |
| 微信小程序端 | Uni-app 编译 mp-weixin | 游客（免注册） | 浏览、地图导览、外链导流 | 微信开发者工具 / 真机 |
| 后端服务 | Flask REST + WebSocket | 上述所有端 | 数据、鉴权、统计、实时推送 | `http://127.0.0.1:5000` |

## 三、同一功能在两端的具体差异

### 3.1 资源列表

| 维度 | Web 管理端 | 小程序端 |
|---|---|---|
| 目的 | **管理**：找到要改的那一条 | **消费**：找到想去的那一个 |
| 数据范围 | 全部（含已下架） | 仅上架 |
| 接口 | `GET /api/attractions/admin`（JWT） | `GET /api/attractions` |
| 交互 | 表格 + 分页 + 状态开关 | 卡片流 + 分类 tab + 上拉加载 |
| 字段 | 含经纬度、排序、外链、操作 | 隐去内部字段，突出 summary/view_count |

### 3.2 地图

| 维度 | Web（管理端/大屏） | 小程序端 |
|---|---|---|
| 地图引擎 | Leaflet + 本地 GeoJSON（离线可用） | 微信原生 `<map>`（需联网底图） |
| 底图 | 海宁市行政边界多边形 | 腾讯地图底图 |
| 交互 | 鼠标悬停、弹窗、缩放 | 双指缩放、marker 点击卡片、定位按钮 |
| 性能策略 | 一次性渲染全部点位 | 分类筛选降低单屏 marker 数 |

### 3.3 数据实时性

| 维度 | Web 大屏 | 小程序端 |
|---|---|---|
| WebSocket | 订阅 `/ws` 的 `new_data` | 不订阅（仅上报） |
| 数据刷新 | 收到事件即更新 KPI/图表/流 | 每次进入页面重新拉取 |
| 降级策略 | 断线重连 + 15 秒兜底轮询 | 请求失败提示重试 |

## 五、数据一致性说明

多端共用同一 MySQL 库，**不存在端侧副本**，因此天然满足"同一数据源"要求。具体保证机制：

1. **唯一写入入口**：资源数据只能通过后台接口变更，小程序端只读。
2. **写后失效**：后台任何写操作都会 `invalidate_attraction_cache()`，清除 Redis 中 `jrt:attraction:map` / `jrt:attraction:meta`，避免出现"后台改了、地图没变"。
3. **统计口径统一**：大屏 `today` 指标与 `POST /api/log` 返回的 `metrics` 由同一函数 `today_metrics()` 计算，不会出现两处数字不一致。
4. **浏览量原子自增**：`UPDATE attraction SET view_count = view_count + 1`，避免多端并发读改写导致丢更新。
5. **WebSocket 只做增量**：大屏首屏拉 `overview`，之后只消费 `new_data` 的增量，避免每来一条日志就全量查询数据库。

## 六、多端适配要点

| 端 | 适配措施 |
|---|---|
| Web 后台 | Element Plus 栅格（`xs/sm/lg` 断点）+ 侧栏固定 + 表格横向滚动；1366×768 起可用 |
| Web 大屏 | CSS Grid 三列布局，1400px 以下自动降为两列；ECharts 监听 `resize` |
| 小程序 | 全部使用 `rpx` 相对单位；`safe-area` 适配刘海屏；地图页留出底部卡片高度 |
